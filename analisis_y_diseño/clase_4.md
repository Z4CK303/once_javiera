### Resumen: clase 4

Este documento presenta los conceptos principales relacionados con las Historias de Usuario dentro de las metodologías ágiles, los principios de calidad INVEST y las actividades prácticas orientadas a su análisis y aplicación.

### 1. Concepto de Historia de Usuario
Descripción: Una Historia de Usuario es una breve descripción de una necesidad o funcionalidad del sistema planteada desde el punto de vista del usuario final. Su finalidad es destacar el beneficio que aporta una característica, promoviendo la comunicación entre el cliente y el equipo de desarrollo.
Formato habitual:

Como [tipo de usuario o perfil]
Necesito [acción o funcionalidad requerida]
Para [beneficio o propósito que se desea alcanzar]

Ejemplo:

"Como usuario de una aplicación bancaria, necesito consultar el saldo de mi cuenta desde la pantalla inicial para conocer mi disponibilidad de dinero de forma rápida."

### 2. Principios INVEST para evaluar Historias de Usuario

Una Historia de Usuario de buena calidad debe seguir los criterios definidos por el modelo INVEST, los cuales permiten que sea clara, útil y manejable durante el desarrollo:

I - Independiente: La historia debe poder implementarse sin depender directamente de otras funcionalidades.
N - Negociable: Su contenido puede ser discutido y ajustado entre los involucrados según las necesidades del proyecto.
V - Valiosa: Tiene que generar un beneficio concreto para el usuario o aportar valor al producto.
E - Estimable: Debe permitir que el equipo determine aproximadamente el esfuerzo necesario para su realización.
S - Pequeña: Debe tener un alcance reducido que facilite su desarrollo dentro de un ciclo de trabajo corto.
T - Comprobable: Es necesario que pueda evaluarse mediante pruebas para confirmar que cumple con lo solicitado.

### 3. Criterios de aceptación: validación de una Historia de Usuario
Descripción: Los criterios de aceptación representan las condiciones que deben cumplirse para considerar una Historia de Usuario finalizada y aprobada por los interesados.
Estructura basada en Dado / Cuando / Entonces:
Dado: Define la situación inicial o el contexto del sistema.
Cuando: Indica la acción realizada por el usuario o un evento específico.
Entonces: Describe la respuesta o comportamiento esperado del sistema.

### 4. Diferencias entre Historias de Usuario y Casos de Uso
Aspecto	Historias de Usuario (Metodología Ágil)	Casos de Uso (Enfoque Tradicional/UML)
Objetivo principal	Priorizar el valor entregado al usuario y facilitar la comunicación.	Especificar de manera detallada cómo interactúa el sistema ante diferentes situaciones.
Nivel de detalle	Descripciones cortas acompañadas de criterios de aceptación.	Documentos más extensos con escenarios, excepciones y detalles funcionales.
Usuarios principales	Clientes, responsables del negocio y equipos de desarrollo.	Analistas, arquitectos de software y desarrolladores técnicos.

### 5. Actividades y ejercicios prácticos del módulo

Los ejercicios del módulo están orientados a fortalecer la comprensión de las Historias de Usuario mediante actividades como:

Evaluar si una Historia de Usuario cumple con los principios INVEST, identificando problemas como un tamaño excesivo o una falta de valor.
Reconocer correctamente los elementos de la estructura Como / Necesito / Para dentro de una historia.
Analizar criterios de aceptación y determinar si los escenarios planteados cumplen con las condiciones esperadas del sistema.
